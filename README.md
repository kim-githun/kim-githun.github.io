# 부동산 시장 온도계

공개 통계(한국은행 ECOS · KOSIS)로 수도권과 지방의 주택시장 과열도를 계산해 보여주는 정적 사이트입니다.
서버가 없습니다. GitHub가 매주 한 번 데이터를 갱신하고 사이트를 다시 배포합니다.

## 폴더 구조

| 경로 | 내용 | 직접 고치나 |
|---|---|---|
| `config.json` | 사이트 주소, 필명, 문의 이메일, 운영자 소개, 애드센스 ID | **예** — 출시 전에 채우세요 |
| `data/market.json` | 지표 값 (자동 갱신) | 주택구입부담지수만 분기마다 손으로 |
| `content/` | 생활 가이드 3편(`guidebook.py`), 통계 해설 12편, 변경 기록(`changelog.py`), 연혁, 안내 페이지 원문 | 글을 고칠 때 |
| `blog/` | 네이버 블로그용 Q&A 원고 (사이트에는 안 올라감) | 붙여 넣을 때 `[사이트 주소]` 를 바꿈 |
| `sources.json` | API 배선도와 안전장치 기준 | 거의 안 고침 |
| `refresh.py` | 데이터 갱신 + 안전장치 | 안 고침 |
| `build.py` | 사이트 생성기 | 안 고침 |
| `public/` | 생성된 사이트 (자동 생성, 저장소에 올리지 않음) | 안 고침 |

## 처음 한 번 — 출시 순서

> 현재 배포: GitHub Pages 무료 주소 **https://kim-githun.github.io** (저장소 `kim-githun/kim-githun.github.io`). 아래 1번(도메인)과 5번(도메인 연결)은 나중에 자체 도메인을 살 때만 하면 됩니다.
> 필명·문의 이메일을 채우기 전에는 모든 페이지가 검색엔진 색인 금지(noindex) 상태입니다.


1. **도메인 구입** — `.kr` 또는 `.com`. 가비아·후이즈 등에서 연 1~3만 원 선입니다.
2. **GitHub 저장소 만들기** — 이 폴더 전체를 올립니다(`public/` 제외).
3. **API 키 등록** — 저장소 → Settings → Secrets and variables → Actions → New repository secret
   - `ECOS_KEY` : 한국은행 ECOS 인증키
   - `KOSIS_KEY` : KOSIS 인증키
4. **Pages 켜기** — Settings → Pages → Source 를 **GitHub Actions** 로.
5. **도메인 연결**
   - `config.json` 의 `site_url` 에 `https://내도메인` 을 적고 올립니다. (CNAME 파일은 자동 생성)
   - 도메인 등록처 DNS 에 A 레코드 4개: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - `www` 를 쓰려면 CNAME 레코드 `www` → `<GitHub아이디>.github.io`
   - Settings → Pages → Custom domain 에 도메인 입력, **Enforce HTTPS** 체크
6. **`config.json` 채우기** — `pen_name`, `contact_email`, `operator_bio`. 비어 있으면 페이지에 노란 `[입력 필요]` 표시가 나옵니다.
7. **검색 등록** — Google Search Console, 네이버 서치어드바이저에 사이트 등록 후 `https://내도메인/sitemap.xml` 제출.
8. **애드센스 신청** — 노란 표시가 하나도 없는지 확인한 뒤 신청. 승인되면 `adsense_client` 에 `ca-pub-...` 를 적고 올리면 광고 코드와 `ads.txt` 가 자동으로 붙습니다.

개인정보처리방침에 "문의 메일 계정에 2단계 인증을 설정한다"고 적혀 있습니다. 문의용 메일을 만들 때 실제로 켜 두세요.

## 매주 자동으로 일어나는 일

금요일 09:00(KST)에 `.github/workflows/refresh.yml` 이 돕니다.

1. 안전장치 테스트
2. `refresh.py update` — 새 값을 받아 6단계 검사
   - 계열 혼입 · 지문(통계표명·항목명·단위) 대조 · 값 범위 · 급변 · 시점 역행 · 교차 검증
3. 통과한 값만 `data/market.json` 에 저장, 검사 기록은 `data/log.jsonl` 에 남김
4. `build.py` 로 사이트 생성 → 배포

게시가 보류되면 작업이 **실패(빨간 X)** 로 표시되고 GitHub 가 메일을 보냅니다. 사이트는 그래도 다시 배포되며, 오래된 지표는 '갱신 지연'으로 표시되고 점수에서 빠집니다.

### 메일이 왔을 때

- 사이트의 **산출 방법 → 최근 갱신 기록** 에서 어떤 지표가 왜 걸렸는지 봅니다.
- **보류(급변)** — 원자료(KOSIS·ECOS)에서 그 값이 맞는지 확인합니다. 맞으면 저장소 → Actions → 지표 갱신과 배포 → Run workflow → `accept` 칸에 지표 이름(예: `base`)을 넣고 실행합니다.
- **거부(지문 불일치)** — 통계표가 바뀌었다는 뜻입니다. 손대지 말고 확인을 요청하세요.
- **교차 검증 실패** — 지표끼리 말이 안 맞습니다. 역시 확인을 요청하세요.

## 글을 고칠 때 — 변경 기록

가이드나 해설을 고치면 `content/changelog.py` 맨 위에 한 줄을 추가합니다.

- `추가` 새 글 · `개정` 제도·수치 변경이나 구성 변경 · `정정` 사이트가 틀렸던 것 (무엇이 틀렸고 무엇으로 고쳤는지 둘 다)
- 가이드를 다시 검토했으면 `content/guidebook.py` 의 `REVIEWED` 날짜도 바꿉니다. 이 날짜가 페이지의 '검토' 날짜와 구조화 데이터의 수정일이 됩니다.
- 종부세 가이드는 시즌 가이드입니다. 매년 9월 초 공시가격·특례 신청 기간·개편안 확정 여부를 다시 확인하세요.

## 검색어 — 무엇을 노리고, 맞는지 어떻게 확인하나

- `content/keywords.py` 가 페이지마다 **주 검색어 1개**와 보조 검색어, 검색 결과용 제목을 정합니다. 본문 제목(H1)과는 따로입니다.
- `build.py` 가 마지막에 점검합니다: 같은 주 검색어를 두 페이지가 노리는지, 제목·설명에 주 검색어 낱말이 있는지, 설명 길이.
- 실측 확인:
  1. `python3 tools/keywords.py batches` → 네이버 검색광고 키워드도구에 한 줄(5개)씩 넣고 결과를 **다운로드**
  2. 받은 파일을 한 폴더에 모아 `python3 tools/keywords.py report 폴더` → `reports/keywords-날짜.md`
  3. 판정이 '주 검색어 교체'면 keywords.py 의 primary·title 을 바꾸고 변경 기록에 '개정'으로 적습니다.
- '경쟁정도'는 광고주 경쟁입니다. 검색 순위 경쟁이 아닙니다.

## 검색엔진 알림 (IndexNow)

`config.json` 의 `indexnow_key` 와 `site_url` 이 있으면, 배포 뒤 `tools/indexnow.py` 가 **본문이 실제로 바뀐 페이지만** 네이버와 IndexNow 공용 창구에 알립니다. 보낸 기록은 `data/indexnow.json`. 사이트맵의 날짜(lastmod)도 빌드한 날이 아니라 글·데이터가 실제로 바뀐 날입니다.

## 광고 자리 규칙 (build.py 가 자동으로 지킴)

- 첫 화면: 계기 아래 1개. 가이드·해설: 본문 2,500자 이하 최대 2개, 그보다 길면 최대 3개.
- 광고 사이 1,000자 이상, 표·목록·점검표 옆 금지, 목록 페이지에는 없음.
- 애드센스 승인 전에는 점선 틀만 보입니다. 승인 후 자동 광고를 켜되, 전면(비넷) 광고는 처음 8주 동안 끄세요(애드센스 화면 설정).

## 분기마다 손으로 하는 일 — 주택구입부담지수

한국주택금융공사 주택금융통계시스템(houstat.hf.go.kr)에서 서울 K-HAI 새 분기 값을 확인한 뒤,
GitHub 웹에서 `data/market.json` 의 `khai` 항목 `value`·`asof`·`delta` 를 고쳐 저장하면 자동으로 다시 배포됩니다.
